weed/s3api — code graph

File-level map of SeaweedFS's S3 gateway and its satellite catalog APIs: 99 files of package s3api, 35 files of the Iceberg REST catalog, Lance namespace and S3 Vectors servers, 11 collapsed neighbor packages and the collapsed Iceberg maintenance worker; lanes ordered by request flow.

weed/s3api is SeaweedFS's S3-compatible gateway. It is a gorilla/mux HTTP server that authenticates each request (SigV4/V2, presigned URLs, STS/JWT, embedded IAM and bucket policies) and maps the S3 operation onto the filer tree under BucketsPath. On top of filer entries and volume chunks it implements the features S3 clients expect: multipart uploads, versioning, SSE-C/KMS/S3, object lock, tagging, ACLs, CORS and lifecycle. Edges come only from the AST (graphify): symbol-level calls, type references, function values passed (indirect_call, e.g. route registration), embeds and imports, aggregated to file level. Lanes 8-10 add the three catalog servers that run beside the gateway on their own ports (wired in command/s3.go): the Iceberg REST catalog, the Lance Namespace REST server and the AWS-compatible S3 Vectors API. All three keep their records in the S3 Tables catalog (the s3tables/ node); lane 11 is the plugin worker that maintains Iceberg tables by writing the filer directly. No dependency rule is enforced. Those servers register their routes with unexported method values, which the extractor does not draw, so their handler files show no incoming edge from server.go.
