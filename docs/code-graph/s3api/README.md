# weed/s3api and filer code graph

A file-level map of the SeaweedFS S3 gateway, the catalog APIs that run beside it, and the filer it runs on. The structure comes from the AST and the explanations were written by hand. Open `s3api-graph.html` in a browser. It is self-contained, with no server or network needed.

The node descriptions, lane names and viewer labels are in Vietnamese; identifiers, file names, PR numbers and common technical terms (bucket, object, chunk, entry, handler, policy, and so on) are kept in English. This README stays in English.

## What is in it

- **273 nodes:**
  - the 104 non-test files of package `weed/s3api`;
  - the 18 non-test files of the S3 Tables catalog (`weed/s3api/s3tables`, top level only; `s3tablestest` is test support), lane 20;
  - the 43 non-test files of the three catalog servers wired next to the gateway in `command/s3.go`: the Iceberg REST catalog (`weed/s3api/iceberg`, 21 files), the Lance Namespace REST server (`weed/s3api/lance`, 9) and the S3 Vectors API (`weed/s3api/s3vectors`, 13);
  - the filer the gateway runs on: the 60 non-test files of `weed/filer`, the 2 of `weed/filer/empty_folder_cleanup`, the 8 hand-written files of `weed/pb/filer_pb`, one node for the generated gRPC code (`weed/pb/filer.proto`, standing for `filer.pb.go`, `filer_grpc.pb.go` and `filer_vtproto.pb.go`) and the 25 files of the filer gRPC server: the 17 `weed/server/filer_grpc_server*.go` files and the 8 `weed/server/filer_grpc_scope*.go` files that enforce scoped tokens on it (#12904, #12923);
  - 12 collapsed packages, one node each: the 10 neighbor packages package `s3api` imports (`s3err`, `s3_constants`, `policy_engine`, `s3lifecycle` (top-level files only), `s3lifecycle/scheduler`, `lifecycle_xml`, `s3bucket`, `cors`, `s3_objectlock`, `policy`), the Iceberg maintenance worker `weed/worker/tasks/iceberg` and the shared SQL store `weed/filer/abstract_sql`.
- **1,716 edges** (1,380 distinct node pairs), extracted with graphify and aggregated from symbols to files. Edge types are `calls`, `indirect_call` (function values such as route registration), `references`, `embeds` and `imports_from`. No edge was added by hand. graphify resolves a Go package import to every file of that package; those fan-out edges are dropped when the target is a file node (`arrange.py`, `import_fanout_to_file`), so `imports_from` edges only point at collapsed package nodes. `INFERRED` calls that graphify resolved by name onto a method in another file, and that the code shows to be something else, are dropped by name in `arrange.py` (`NAME_COLLISIONS`); each entry says why. A type declared outside the graphed files is pinned by graphify to the first input file that mentions it, so references to it are dropped too (`OUT_OF_SCOPE_TYPES`: `FilerServer`, declared in `weed/server/filer_server.go`).

- **Excluded:** `*_test.go`, test helper packages (`s3tablestest`, `lifecycletest`), `testdata` directories, `policy_engine/examples.go`, `kms_azure.go`, and the test-only hooks `weed/filer/filer_notify_read_testing.go` and `weed/filer/meta_aggregator_testing.go`. The individual filer store backends (`weed/filer/leveldb*`, `mysql`, `redis*` and so on) are outside the scope; only the shared SQL implementation is a node.
- **A known gap in the edges:** the Iceberg, Lance and S3 Vectors servers register their routes with unexported method values (`s.handleX`), and graphify draws no edge for those. Their handler files therefore show no incoming edge from `server.go`. The gateway's own routes (`s3a.XHandler`) are drawn. The gateway calls the filer over gRPC, so no AST edge from lanes 0–11 reaches the filer gRPC server (lane 13); the generated client in `weed/pb/filer.proto` is where the two sides meet. The 124 gateway-to-filer edges go to that node, the `filer_pb` helpers and the filer library code the gateway links in directly (chunk lists, manifests, streaming, `filer.conf`, config file reads).

Each node was curated by reading its source in full. The collapsed worker node was curated from its handler, detection, commit, orphan and filer I/O code; its algorithm files (compaction, delete rewrite, row lineage, geometry) are summarized, not described one by one. The generated-code node was curated from `filer.proto`. The panel shows these fields:

| Field | Content |
| --- | --- |
| character | One-line role |
| what | What the code does |
| why | The consequence if it fails, the design decision behind it, and any compatibility constraint (AWS, Iceberg REST, Lance Namespace, POSIX) |
| when | When it runs |
| ux | What users see |
| if_broken | What breaks if it does |
| gotchas | Non-obvious behavior to know before changing it |
| issue / issue_note | The defect flag and its explanation, where one applies |

### Fixed since the first curation

- `s3api_object_handlers_put.go`: an invalid `x-amz-storage-class` was rejected only after the upload and leaked the chunks. Fixed upstream in [seaweedfs/seaweedfs#12354](https://github.com/seaweedfs/seaweedfs/pull/12354) (`validatePutHeaders` now runs before the body is read); the flag was removed.
- `iceberg/commit_helpers.go`: create-on-commit wrote v{N}.metadata.json non-exclusively and deleted it on any CreateTable error, so concurrent creators could delete the winner's file. Fixed upstream in [seaweedfs/seaweedfs#12474](https://github.com/seaweedfs/seaweedfs/pull/12474) (`195f815`): both create paths stage the file exclusively with a per-request token, discard it only when the catalog refused the registration, and answer 409 on an existing name. The flag was removed, and the CreateTable part of the `iceberg/handlers_table.go` flag with it. The fix's tests pass at `7506e5f`.
- `s3tables/`: three defects of the first flag are fixed upstream, and each was re-checked at `b9866bae`. A table renamed across namespaces can commit again ([seaweedfs/seaweedfs#12515](https://github.com/seaweedfs/seaweedfs/pull/12515), `2143761`). `RenameTable` refuses a source that changed between its reads, and has a REST route ([seaweedfs/seaweedfs#12446](https://github.com/seaweedfs/seaweedfs/pull/12446), `f71c0fe`). Policy `Condition` blocks are validated when stored and an unusable stored one fails safe ([seaweedfs/seaweedfs#12389](https://github.com/seaweedfs/seaweedfs/pull/12389), `15ff5c1`). The node keeps a bug flag for a different defect, found while re-checking.
- `iceberg/handlers_view.go`: since [seaweedfs/seaweedfs#12475](https://github.com/seaweedfs/seaweedfs/pull/12475) a view created without a location has its own directory, so the loser of a concurrent create no longer overwrites the winner's metadata file in that case. The flag stays for the same-location case and for the 200 answer on an existing view.

- `lance/handlers_table.go`: deregister and re-register needed only read permission. Fixed upstream in [seaweedfs/seaweedfs#12552](https://github.com/seaweedfs/seaweedfs/pull/12552) (`eb159f3`): both now require UpdateTable. The flag was removed.
- `auth_signature_v2.go`: the subresources missing from the SigV2 string to sign (`?cors`, `?tagging`, `?object-lock`, `?encryption` and others) are fixed by [seaweedfs/seaweedfs#12575](https://github.com/seaweedfs/seaweedfs/pull/12575) (`917cf53`). The flag stays for the missing Date freshness check.
- Removed from the gotchas during the `917cf534` sync because upstream fixed them: the null-version delete that treated any lookup error as "already gone" (#12482, `s3api_object_versioning.go`), the upload-throttle overshoot (#12559, `s3api_circuit_breaker.go`) and the policy-condition panic on JSON null (#12389, `policy_engine/`).

- `s3tables/`: CreateTable and CreateView no longer wipe a record another create just registered. Fixed upstream in [seaweedfs/seaweedfs#12600](https://github.com/seaweedfs/seaweedfs/pull/12600) (`aa901b7`): `ensureDirectory` creates a missing directory exclusively and keeps one that appeared since the lookup, so the losing create meets the winner's record and answers 409; the Iceberg metadata and stage-create directories are made the same way. Its race tests pass at `4fc41872`. The flag was removed; the node now carries no flag.
- `policy_engine/`: condition values were read through a process-wide cache keyed by `fmt.Sprint` of the value, so `["a", "b"]` and `["a b"]` (or `[]` and `[""]`) shared an entry. A condition of one policy, including a value substituted from `${...}`, could then be compared against another policy's values: one bucket's policy could switch off another bucket's Deny. It was not a flag of this graph; it was found and reproduced while working from it at `4fc41872`. Fixed upstream in [seaweedfs/seaweedfs#12665](https://github.com/seaweedfs/seaweedfs/pull/12665) (`c0509cf`), which removes the cache and normalizes the value on each evaluation. The node's text now records the change; its `s3:authType` flag stays.
- `s3api_object_handlers_delete.go`: the gotcha that a routed versioned delete checked If-Match outside the lock was removed: [seaweedfs/seaweedfs#12624](https://github.com/seaweedfs/seaweedfs/pull/12624) keeps a conditional delete without versionId on the lock path and carries If-Match into the owner's transaction for version deletes.
- `policy_engine/`: presigned SigV4 URLs carried no `s3:authType`, so the AWS-documented "deny presigned URLs" policy did not stop them. Fixed upstream in [seaweedfs/seaweedfs#12762](https://github.com/seaweedfs/seaweedfs/pull/12762) (`f88751c3`); the flag stays for the POST Object half.
- Removed from or rewritten in the gotchas during the `afdb32d2` sync because upstream fixed them: `DeleteBucketOwnershipControls` rewrote the whole bucket entry and skipped the config cache (#12748, `s3api_bucket_handlers.go`); UploadPartCopy wrote the part on the default filer rather than the object's owner (#12668, `s3api_object_handlers_copy.go`); a manifest that failed to resolve on delete was deleted while its data chunks leaked (#12810, `filer_deletion.go`); batch lookup minted read tokens only for the manifest needle, not the data chunks behind it (#12756, `filer_grpc_server_batch_lookup.go`); ListParts listed a part number once per attempt (#12770, `filer_multipart.go`).
- `s3api_public_access_block.go`: `BlockPublicPolicy` and `RestrictPublicBuckets` were stored but never enforced. Fixed upstream in [seaweedfs/seaweedfs#12882](https://github.com/seaweedfs/seaweedfs/pull/12882) (`5afeb20a`): PutBucketPolicy refuses a public policy with AccessDenied when the bucket blocks public policies, and a public policy no longer lets anonymous callers in when the bucket restricts public buckets. Re-checked by reading the code. Authenticated callers, other accounts included, are still allowed by a public policy, which is now a gotcha rather than the flag.

- `s3tables/handler_bucket_get_list_delete.go`: a bucket-policy statement conditioned on the bucket's own tags (`s3tables:TableBucketTag/*`, `aws:ResourceTag/*`) never matched on Get/List/DeleteTableBucket, Get/DeleteTableBucketPolicy and bucket maintenance, because their policy context carried no bucket tags: a "never delete a bucket tagged protected" Deny let the bucket be deleted. Fixed upstream in [seaweedfs/seaweedfs#12958](https://github.com/seaweedfs/seaweedfs/pull/12958) (`da46e334`), which also gives the bucket's tags to `aws:ResourceTag` on namespace, table-create, list and absent-target checks, passes CreateTableBucket's request tags to IAM conditions, reads a listed bucket's policy and tags from one lookup, and rechecks the tags when the bucket policy is deleted. The flag was removed; the remaining gotchas note that Get and Delete still read metadata, policy and tags in three lookups.
- `iceberg/handlers_namespace.go`: UpdateNamespaceProperties wrote back a merged copy of the properties it had read, so two concurrent updates of different keys both answered 200 and one was lost. Fixed upstream in [seaweedfs/seaweedfs#12890](https://github.com/seaweedfs/seaweedfs/pull/12890) (`8046d5c7`): the changes travel as `PropertyChanges` and are applied inside s3tables' compare-checked write, and a write that loses every attempt answers 503 with `Retry-After`. The flag was removed.
- `server/filer_grpc_server_rename.go`: StreamRenameEntry returned on a non-empty target without rolling back its transaction, holding a pooled SQL connection until restart. Fixed upstream in [seaweedfs/seaweedfs#12886](https://github.com/seaweedfs/seaweedfs/pull/12886) (`040ff904`), which also runs the emptiness check inside the transaction. The flag was removed.
- `s3api_acl_helper.go`: a grant without a `Permission` (an optional member of the S3 Grant type) was stored with 200, and every later GetObjectAcl/GetBucketAcl panicked in `buildAccessControlList`. It was not a flag of this graph; it was found and reproduced while working from it. Fixed upstream in [seaweedfs/seaweedfs#12938](https://github.com/seaweedfs/seaweedfs/pull/12938) (`827a3d2a`): a missing or unknown permission answers `MalformedACLError`, and stored grants without one are skipped.

## Regenerating

Run these from the repository root:

```bash
python3 docs/code-graph/s3api/tools/extract.py <graphify-cache-dir> <ast-raw.json>
```

`extract.py` needs graphify installed, and it hardcodes `REPO = /home/user/seaweedfs`; change that line when you run it from another checkout. Run it without `-I`, because it imports the installed `graphify` module. Its seed lists (`NEIGH`, `FILE_PKGS`, `EXTRA_NEIGH`, `FILER_FILE_DIRS`, `FILER_COLLAPSED`, `FILER_SERVER_GLOBS`) and `arrange.py`'s `FILE_PKGS` / `COLLAPSED_EXTRA` / `FILER_FILE_DIRS` / `FILER_SERVER_PREFIXES` / `GENERATED` must agree.

```bash
python3 -I docs/code-graph/s3api/tools/arrange.py <ast-raw.json> docs/code-graph/s3api/layers.json docs/code-graph/s3api/data.json
```

```bash
python3 -I docs/code-graph/s3api/tools/assemble.py docs/code-graph/s3api .
```

`merge_curation.py` adds new curation fields to `curation.json` but never overwrites existing ones; it reports conflicts instead. `assemble.py` fills `viewer-template.html` and reports:

- curation keys with no node
- nodes whose file no longer exists
- uncurated nodes
- lane mismatches

All four must be zero before publishing.

After the code changes, re-run extract and arrange, then run assemble. Any node it reports as uncurated, or whose source changed, needs to be read again before its description can be trusted.
